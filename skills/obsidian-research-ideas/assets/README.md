# 科研灵感库使用规范

## 目的

这里收集尚未成为正式项目的科研问题、观察、假设和方法灵感。目标不是囤积点子，而是让每个值得保留的想法都有来源、验证路径和下一步。

## 三段式工作流

1. **捕捉**：在 `01 Inbox/` 新建笔记并应用模板。先写一句话想法、触发来源和最小行动，不追求一次写完整。
2. **澄清**：能说明研究对象、关键问题和价值后，把笔记移到 `02 Idea Notes/`，状态改为 `developing`。
3. **验证**：开始检索、数据检查、访谈或小实验时改为 `testing`。能够独立推进时，链接到正式项目笔记。

## 状态规范

| 状态 | 使用场景 |
| --- | --- |
| `seed` | 新捕捉、尚待梳理 |
| `developing` | 正在形成问题、机制和方法 |
| `testing` | 正在执行最小验证 |
| `parked` | 当前不做，但保留明确的重访条件 |
| `archived` | 已否定、已完成转化或已合并 |

`maturity` 表示想法的成形程度（1–5），`priority` 表示当前资源安排（low/medium/high）。二者不要混用。

## 命名与属性

- 文件名：`YYYY-MM-DD - 简短标题.md`。
- 主题词：保持 1–3 个稳定词汇，避免为同一概念创造多个近义标签。
- 关联项目、论文和概念：使用 Obsidian Wikilink。
- 日期：统一为 `YYYY-MM-DD`。
- 所有想法笔记保留 `type: research-idea` 和 `research-idea` 标签。

## 每周复盘（建议 15–30 分钟）

- 清理 `01 Inbox/`，为每个想法决定：推进、暂存、合并或归档。
- 检查推进中想法的 `next_action` 是否足够具体。
- 为重要想法补一条反证或替代解释，防止只收集支持证据。
- 将成熟度达到 4–5 的想法转入正式项目，灵感笔记保留为来源记录。

## 归档与删除

- 优先归档，不直接删除；写明停止原因或合并去向。
- 重复想法保留一个主笔记，其他笔记链接到主笔记后归档。
- 只有确认无信息价值且无引用关系时才删除。
